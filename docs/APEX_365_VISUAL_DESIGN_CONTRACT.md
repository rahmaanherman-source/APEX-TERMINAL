# APEX 365 — VISUAL DESIGN CONTRACT

**Status:** LOCKED / CANONICAL
**Owner Surface:** APEX 365 Build Workspace

## PURPOSE

A Visual Design Contract turns an uploaded visual reference plus explicit owner instructions into a governed design requirement for the APEX 365 builder.

A reference image is not merely an asset. It may define the required visual identity, structure, behavior, theme, or characteristics of a page, component, character, collection, or other build element.

## OWNER FLOW

`UPLOAD → IDENTIFY → DESCRIBE → CLASSIFY → RELATE → CONFIRM → LOCK → BUILD → VERIFY`

Gabby must analyze uploaded references, preserve the original, identify likely relationships, and present the interpretation for owner confirmation. The owner confirmation is authoritative.

## CONTRACT RECORD

Each contract records:

- contract ID
- reference image/file IDs
- owner-defined name
- element type
- page/component/collection target
- exact owner instructions
- required visual characteristics
- color/theme/typography/layout requirements when specified
- related contracts and collections
- locked characteristics
- permitted upgrades
- provenance
- creation/update timestamps
- verification evidence

## SINGLE VS COLLECTION

A single reference may define an element requiring individual attention, such as a Homepage, Gabby, CSS/theme, navigation shell, or specific component.

Multiple references may be uploaded together as a collection. Gabby must classify and group related references without losing individual identity or provenance.

Example: multiple Mermaid references may form a **MERMAIDS** collection while each Mermaid remains independently addressable.

Mixed uploads must be separated into appropriate groups according to explicit owner labels and confirmed system classification.

## LOCK LAW

**LOCKED means DO NOT DEVIATE WITHOUT OWNER AUTHORIZATION.**

The implementation may be improved, optimized, or extended, but locked characteristics must remain true unless the owner explicitly changes the contract.

A contract is not a copy command. It is a design constraint and source-of-truth reference.

## COMPOSITION

Existing locked contracts are preserved. New references may be added, related, or composed with existing contracts without replacing them.

`EXISTING CONTRACT + NEW APPROVED REFERENCE → EXTEND / LINK / COMPOSE`

Never silently overwrite a locked design requirement.

## GABBY VERIFICATION

Before build, Gabby must identify what the reference is believed to represent and surface any ambiguity.

After owner confirmation, the contract becomes authoritative for that element.

During build, compare implementation against the contract. If a locked requirement is violated, report the mismatch and do not mark the design verified.

## APEX LAWS

**KEEP WHAT MATTERS. MERGE WHAT’S THE SAME. ADD WHAT’S NEW. LINK WHAT’S CONNECTED. LEAVE THE REST IN ARCHIVE.**

**REUSE FIRST → EXTEND SECOND → GENERATE LAST.**

No fake visual verification. No invented characteristics. No silent reinterpretation.

## APEX 365 BOUNDARY

Visual Design Contracts belong to the APEX 365 owner/build system. Customer-facing products consume approved contracts; they do not redefine the owner workspace.

**THIS CONTRACT IS LOCKED UNTIL THE OWNER EXPLICITLY CHANGES IT.**
